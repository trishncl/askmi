# AA's Lomi — Project Scaffold

This is a **structure, not a finished app**. Every file under `lib/` outside
of the ones listed as "real content" below is a placeholder comment —
build the logic yourself, phase by phase, using this as the map.

## What's real right now (Phase 0 — Setup)

- `pubspec.yaml` — finalized dependency list
- `firebase.json`, `firestore.rules` — baseline security rules
- `lib/firebase_options.dart` — placeholder, regenerate with `flutterfire configure`
- `lib/core/theme/app_colors.dart`, `app_theme.dart` — brand palette already decided
- `lib/core/constants/firestore_collections.dart` — matches the finalized schema
- `lib/main.dart`, `lib/app.dart` — a deliberately minimal "Phase 0 complete" checkpoint screen

Everything else in `lib/` is a stub: just a comment naming its phase and
what it should eventually contain. Nothing imports these yet, so the
project should still run — it just shows the Phase 0 placeholder screen.

## Getting this running locally

1. This zip does **not** include Android/iOS/Web platform folders — those
   get generated by the Flutter CLI, not handwritten. In an **empty**
   folder, run:
   ```
   flutter create --project-name aa_lomi_owner .
   ```
   Then copy everything from this scaffold **on top of** that (it will ask
   to overwrite `pubspec.yaml` and `lib/main.dart` — say yes, ours are the
   real ones).
2. `flutter pub get`
3. `dart pub global activate flutterfire_cli` then
   `flutterfire configure --project=<askmi-aa-s-lomi-app>` — replaces the
   placeholder `lib/firebase_options.dart`.
4. `firebase deploy --only firestore:rules` (needs `firebase use --add` first
   if this is a new folder — see earlier troubleshooting).
5. `flutter run` — you should see "Phase 0 complete — Firebase connected."
   If you see that, Phase 0 is done. Move to Phase 1.

## Build order (matches the roadmap from planning)

1. **Data layer** — `models/`, `repositories/`. Turn each schema table from
   `AA_Lomi_Firestore_Schema.docx` into a model class + repository.
2. **Auth core** — `services/auth_service.dart`, `staff_account_service.dart`,
   `providers/app_providers.dart`, `features/auth/auth_gate.dart`. Manually
   bootstrap your first Owner (Auth user + matching `users/{uid}` doc)
   before writing any UI — test role lookup with nothing but the Firebase
   Console.
3. **Entry UI** — `features/auth/landing_page.dart`, `login_page.dart`,
   and the shared `core/widgets/*`.
4. **Owner build**, one module per sprint, in this order: Dashboard → Sales
   → Inventory → Products → Menu Management → Branches → Reports →
   Settings (last — highest privilege).
5. **Manager & Cashier** — Manager reuses Owner's pages with `BranchScope`
   locked to their branch; Cashier POS is its own screen, build it last.
6. **Security hardening** — branch-isolation rules (the gap flagged in
   `firestore.rules`'s comment), data-shape validation in rules.
7. **QA & demo prep** — real-device test, fresh-clone test, demo script.

Each stub file's comment repeats which phase/order it belongs to, so you
can `grep -rn "PHASE 1"` (etc.) across `lib/` any time you want a checklist
of what's left in the current phase.
